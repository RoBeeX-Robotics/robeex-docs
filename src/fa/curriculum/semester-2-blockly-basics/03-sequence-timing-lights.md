# جلسه ۳: ترتیب، زمان‌بندی و چراغ‌ها

چراغ‌ها بهترین خروجی برای دیدن منطق برنامه‌اند: نتیجه واضح است و پرنده حرکت نمی‌کند. در این جلسه با یک الگوی نوری می‌بینید جابه‌جایی بلوک یا تغییر واحد زمان دقیقاً چه اثری دارد.

## در پایان این جلسه می‌توانید

- مسیر اجرای یک پشته را از بالا به پایین دنبال کنید؛
- `Wait` را با واحد ثانیه و میلی‌ثانیه تنظیم کنید؛
- رنگ RGB و روشنایی را جدا کنترل کنید؛
- قبل از Run جدول زمانی بسازید؛
- با تغییر فقط یک پارامتر، علت تفاوت دو اجرا را توضیح دهید.

::: teacher آماده‌سازی پیش از کلاس
یک برنامه صحیح «سبز–زرد–قرمز» و سه نسخه خطادار آماده کنید: Wait بدون واحد/مقدار مناسب، روشنایی صفر، و دو رنگ جابه‌جا. ملخ‌ها باز یا ربات کاملاً ایمن روی زمین باشد؛ هیچ بلوک Flying در Workspace باقی نماند.
:::

## ۱. بلوک‌های Lights را بخوانید

<figure class="curriculum-media is-narrow">
  <img src="/assets/curriculum/semester-2/blockly-led-lighting-blocks.webp" alt="تصویر جداشده بلوک‌های روشنایی پایین، RGB، روشنایی و حالت LED" width="593" height="570" loading="eager" decoding="async">
  <figcaption>رنگ، روشنایی و انتخاب LED کارهای متفاوت‌اند. برچسب بلوک نسخه خود را پیش از مقداردهی بخوانید.</figcaption>
</figure>

نمونه‌های موجود در دسته Lights:

- تنظیم روشنایی چراغ پایین به درصد؛
- خاموش‌کردن چراغ با روشنایی صفر؛
- انتخاب رنگ RGB؛
- تنظیم روشنایی LEDهای RGB؛
- انتخاب یک LED خاص یا حالت نمایش، اگر نسخه برنامه پشتیبانی کند.

::: teacher نکته مربی — رنگ با روشنایی فرق دارد
یک بلوک رنگ قرمز با روشنایی صفر نشان دهید. بپرسید «رنگ انتخاب شده، پس چرا چیزی نمی‌بینیم؟» پاسخ: رنگ و شدت دو پارامتر مستقل‌اند؛ روشنایی صفر خروجی را خاموش می‌کند.
:::

## ۲. Timing فقط «صبرکردن» نیست؛ واحد دارد

<figure class="curriculum-media is-narrow">
  <img src="/assets/curriculum/semester-2/blockly-wait-and-timing-blocks.webp" alt="تصویر جداشده بلوک‌های Wait بر حسب ثانیه و میلی‌ثانیه" width="472" height="551" loading="lazy" decoding="async">
  <figcaption>`Wait 3 seconds` با `Wait 500 milliseconds` یکی نیست. 1000ms برابر 1s است.</figcaption>
</figure>

- 500ms = 0.5s
- 1000ms = 1s
- 2500ms = 2.5s

`Wait` اجرای پشته را برای زمان مشخص نگه می‌دارد؛ معنی آن «صبر کن تا هر حرکتی حتماً کامل شود» نیست. در مأموریت پروازی باید رفتار همان بلوک و نسخه نرم‌افزار نیز فهمیده شود.

::: teacher تمرین واحد
چهار کارت 250ms، 0.5s، 1000ms و 2s بدهید. هنرجو آن‌ها را از کوتاه به بلند بچیند و جفت‌های برابر را پیدا کند. اشتباه واحد در برنامه پروازی می‌تواند زمان را هزار برابر عوض کند.
:::

## ۳. جدول زمانی را قبل از ساخت پر کنید

مأموریت: LED ابتدا سبز، سپس زرد و در پایان قرمز شود؛ هر حالت زمان مشخص دارد.

| زمان شروع | دستور | مقدار | زمان ماندن | انتظار ما |
| --- | --- | --- | --- | --- |
| 0s | Set RGB | سبز | 1s | آماده |
| 1s | Set RGB | زرد | 2s | در حال انجام |
| 3s | Set RGB | قرمز | 1s | پایان |
| 4s | Set Brightness | 0% | — | خاموش |

::: teacher نکته مربی — زمان تجمعی
از هنرجو بپرسید قرمز در چه ثانیه‌ای شروع می‌شود. پاسخ 3s است، چون 1+2. اگر گفت 2s، مدت یک مرحله را با زمان از آغاز مخلوط کرده است.
:::

## ۴. ساخت نسخه ۱

1. برنامه جلسه قبل را Duplicate و `Traffic-v1` نام‌گذاری کنید.
2. بلوک سبز و سپس `Wait 1s` را متصل کنید.
3. بلوک زرد و `Wait 2s` را اضافه کنید.
4. بلوک قرمز و `Wait 1s` را اضافه کنید.
5. در پایان روشنایی را صفر یا رنگ را طبق دستور مربی خاموش کنید.
6. با انگشت مسیر Start تا آخر را دنبال کنید.
7. جدول پیش‌بینی را با برنامه تطبیق دهید.
8. پس از تأیید بازبین، Run و زمان‌ها را مشاهده کنید.

<figure class="curriculum-media">
  <img src="/assets/curriculum/semester-2/blockly-rgb-blinker-program.webp" alt="نمونه برنامه Blockly شامل تغییر RGB و Wait" width="311" height="245" loading="lazy" decoding="async">
  <figcaption>این تصویر برای خواندن ساختار است. برنامه کلاس باید طبق جدول زمانی خود گروه ساخته شود، نه با کپی عددهای تصویر.</figcaption>
</figure>

::: teacher قبل از اجرا
بازبین سه مورد را با صدای بلند تأیید کند: هیچ بلوک پرواز نداریم؛ واحد همه Waitها روشن است؛ روشنایی در محدوده قابل مشاهده و مجاز قرار دارد. سپس نتیجه را قبل از Run جمله‌به‌جمله بخواند.
:::

## ۵. آزمایش یک‌متغیره

نسخه را Duplicate و `Traffic-v2` بنامید. فقط مدت زرد را از 2s به 4s تغییر دهید. هیچ رنگ، ترتیب یا روشنایی دیگری تغییر نکند.

| نسخه | متغیر تغییرکرده | پیش‌بینی | نتیجه | آیا پیش‌بینی درست بود؟ |
| --- | --- | --- | --- | --- |
| v1 | — |  |  |  |
| v2 | Wait زرد |  |  |  |

سپس یک نسخه کاغذی بسازید که سبز و قرمز جابه‌جا شده‌اند. بدون Run توضیح دهید چرا این خطا فقط «ظاهر متفاوت» نیست و می‌تواند معنی وضعیت را عوض کند.

::: teacher نکته مربی — علت را قابل دفاع کنید
اگر گروه هم‌زمان رنگ و زمان را تغییر داد، نتیجه قابل نسبت‌دادن به یک علت نیست. آن‌ها را به v1 برگردانید و فقط یک تغییر انجام دهید. این عادت پایه اشکال‌زدایی جلسه ۹ است.
:::

<div class="lesson-checkpoint">
<strong>توقف و بررسی:</strong> اگر LED مطابق انتظار نیست، اول مسیر پشته، سپس مقدار روشنایی، بعد رنگ و در آخر اتصال دستگاه را بررسی کنید؛ چند چیز را هم‌زمان عوض نکنید.
</div>

::: warning
روشنایی 100٪ می‌تواند مصرف باتری را بالا ببرد. برای تمرین از مقدار متوسط استفاده کنید و پس از پایان، LED را خاموش یا به حالت تعیین‌شده مربی برگردانید.
:::

## کوییز نهایی

1. `Wait 1500ms` چند ثانیه است؟
2. اگر رنگ آبی انتخاب شده ولی روشنایی صفر است چه می‌بینیم؟
3. چرا تغییر هم‌زمان رنگ و زمان یک آزمایش خوب نیست؟

::: teacher پاسخ و معیار
1.5s؛ خروجی خاموش؛ چون علت تفاوت نتیجه معلوم نمی‌شود. برنامه نهایی باید جدول پیش‌بینی، پشته متصل و نسخه دوم با دقیقاً یک تغییر داشته باشد.
:::
